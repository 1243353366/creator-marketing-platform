# Engineering lessons extracted from this build's failures

Each of these was a real failure encountered while building and
launching this app, kept here as the extracted value. The raw
mistakes are gone; the practices remain and are enforced where
noted.

1. **A pipe masks the failure it carries.** `cmd | tail -1` exits 0
   even when `cmd` fails, so a broken migration chain once
   "succeeded" to the next step. Practice: scripts check exit codes
   explicitly; never judge a step by what prints after it.

2. **A pattern-matched kill can kill your own command.** Broad
   `pkill -f` patterns matched the wrapper shell's own command line
   and silently cancelled the tool call. Practice: target processes
   by exact `ps` fields, never by a substring your own invocation
   contains.

3. **Resources die with their parent process.** An embedded
   Postgres exported into a subshell's environment stopped the
   moment the subshell exited, so the consumer never connected.
   Practice: create the resource and consume it in the same
   process (see scripts/migrate.py).

4. **A resource leak presents as a hang, not an error.** Unclosed
   SQLAlchemy sessions exhausted the pool and requests stalled
   until timeout. Practice: scoped sessions with app-context
   teardown (app/db.py); every acquire has an owner.

5. **Imported globals go stale.** `from .db import _Session`
   captured None; `init_db` later rebound the module global and the
   teardown crashed. Practice: import the accessor function, not
   the mutable module attribute it returns through.

6. **"Works on my machine" is an environment claim, not evidence.**
   The release gate passed locally under an exported PYTHONPATH and
   failed every CI job because `python script.py` puts the script
   directory on sys.path, not the caller's cwd. Practice:
   environment-independent code plus a clean-environment test.

7. **The runner must be in the manifest.** CI installed
   "successfully" while pytest was absent, so the test step failed
   for lack of a runner, not a test. Practice: every tool CI invokes
   is pinned in requirements-dev.txt.

8. **An autogenerated artifact can be empty and still "succeed".**
   Alembic autogenerate produced a migration with zero tables
   because env.py never imported the models module. Practice:
   verify the artifact's content, not the command's exit — count
   the tables after upgrade.

9. **Assertions must match rendering reality.** A journey check
   hunted for `<urlset` while Jinja honestly escaped it to
   `&lt;urlset`. Practice: assert against what the system actually
   emits.

10. **Cite only executable evidence.** The failure database refused
    a retirement that cited a test name that did not exist. That
    refusal was the system working. Practice: no claim without an
    artifact you can run.

**The meta-lesson** (this is F-GATE-CHAIN's lesson found again in
new clothes): several failures were masked by success signals —
green pipes, successful installs with missing tools, empty
artifacts, redirects that never arrived. Verifying the artifact
itself, not the ceremony around it, is the one durable rule.
